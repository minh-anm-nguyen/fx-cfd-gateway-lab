## Blocked scenarios and why

These did not run here. The reason is part of the evidence: a blocked scenario
is an admitted gap, never a silent pass. Most of them need PostgreSQL, a second
node or real hardware, none of which this lab has.

## What this report does not establish

Design doc section 30 asks for this to be stated rather than left implicit.

- The runnable backend here is SQLite, not the PostgreSQL 17 the design targets.
  `migrations/0001_core.sql` carries the PostgreSQL schema, and the store logic is
  written against an engine-neutral interface, but no scenario in this report was
  executed against PostgreSQL.
- No replica, no WAL archive and no point-in-time recovery were exercised. Every
  scenario that needs them is BLOCKED above.
- A process terminated without unwinding is not a power cut. Durability past the
  fsync contract needs hardware whose write cache is under test control.
- Zero failures in N trials is not proof. These results describe this lab on this
  host, and nothing about a broker's real Rules of Engagement.
