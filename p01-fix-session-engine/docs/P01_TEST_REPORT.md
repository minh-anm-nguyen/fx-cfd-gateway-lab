## Blocked scenarios and why

These did not run here. The reason is part of the evidence: a blocked
scenario is an admitted gap, never a silent pass.

| id | priority | scenario | reason |
|---|---|---|---|
| A-19 | P0 | a failed TLS handshake must not fall back to plaintext | TLS is out of v1 scope; startup refuses tls_enabled instead of downgrading, which scenario C-19 asserts. A real handshake test needs a TLS stack. |
| G-09 | P0 | a simulated power loss respects the fsync contract | the crash suite terminates a process without unwinding, which does not test hardware durability. A real power cut needs a VM or a machine with the write cache under test control: it stays out of lab scope and is declared rather than assumed. |
| I-07 | P1 | heartbeat behaviour under fifty thousand messages per second | throughput measurement needs the benchmark harness and a quiet machine; it is reported separately rather than asserted as a pass or fail here. |
| I-08 | P1 | parse latency percentiles are explained by metrics | latency percentiles belong to the benchmark report, not to a functional gate; the doc forbids presenting sanitizer builds as production latency. |
| I-10 | P1 | a disk nearing its quota warns before writes fail | v1 has no filesystem quota monitor: the engine reacts to the store error it receives (G-10, I-09) rather than predicting it. A quota watcher is backlog. |
| I-11 | P1 | file descriptors do not grow over ten thousand reconnects | covered at the socket layer by A-12, which counts opens against closes over a thousand flaps. A real ten thousand cycle soak belongs to the soak job. |
| I-14 | P1 | an unreachable metrics backend does not affect sequencing | v1 keeps metrics in process with no exporter, so there is no backend to make unreachable. I-12 shows the engine does no background work. |
| I-15 | P1 | a full logging partition does not corrupt session state | v1 writes audit records to the store and an in-memory log; there is no separate log partition yet. The store path is covered by G-10 and G-12. |
| J-01 | P0 | an impostor peer is rejected by TLS identity | TLS is out of v1 scope. Startup refuses tls_enabled rather than silently running plaintext (C-19), and J-02 records that CompID is not authentication. |
| J-13 | P0 | an expired certificate chain never falls back to plaintext | same reason as J-01: there is no TLS stack in v1 to present a bad chain to. |
| K-04 | P0 | a kill during a durability commit recovers safely | runs in the crash suite, which spawns a child and terminates it at an exact store failpoint; an in-process test cannot model an abrupt kill. |
| K-05 | P0 | two threads cannot reserve the same sequence number | the engine is single owner by construction (design doc 4.2), so a multi-threaded writer is not a supported configuration and there is no behaviour to assert. Ownership across processes is enforced and tested by C-18, G-21 and K-14. |
| K-08 | P1 | a hot reload of the heartbeat interval is applied safely | v1 has no hot reload: configuration is read once at startup and a changed HeartBtInt is rejected at the next Logon (C-15). |
| K-13 | P0 | an out of memory kill is followed by a safe recovery | the recovery path is the same as any abrupt termination and is exercised by the crash suite; forcing a real cgroup kill needs a container, not a unit test. |
| L-01 | P0 | a QuickFIX acceptor completes Logon, heartbeat and logout | QuickFIX/C++ is not available in this environment, and the design doc is explicit that a peer you wrote yourself cannot prove your own compliance. The loopback scenario e2e-loopback is the nearest available evidence: a real TCP round trip against a separately written wire implementation. |
| L-03 | P0 | a QuickFIX peer logging on with a higher sequence recovers | same dependency as L-01. The behaviour itself is covered against the scripted peer by C-11 and E-11. |
| L-05 | P0 | a peer without the requested TLS feature is not downgraded | TLS is out of v1 scope: startup refuses tls_enabled outright (C-19) instead of negotiating down to plaintext. |
| SAN-02 | P0 | AddressSanitizer reports nothing across the suite | this toolchain ships no libasan: mingw-w64 GCC has no AddressSanitizer runtime, so -fsanitize=address does not link. The CMake option FIXSE_ASAN and scripts/run_sanitizers.sh --asan are in place for the Linux target the design doc names; SAN-01 is the undefined behaviour evidence available here. |
| SAN-03 | P1 | ThreadSanitizer reports nothing across the suite | same missing runtime as SAN-02, and the engine is single threaded by construction, so there is little for TSan to find in v1. The option is kept for the Linux target and for the threaded work in Project 07. |
